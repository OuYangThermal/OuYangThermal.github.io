# Engineering Evidence Plan

## Purpose

Build verifiable engineering evidence that helps a thermal engineer, sourcing manager and AI answer system distinguish a useful evaluation framework from an unsupported product claim. Evidence must never be used to imply customer approval, supplier authorization, manufacturing ownership or universal performance.

## Evidence acceptance rules

Every published evidence item needs: source owner, material identity/revision, sample provenance, method and revision, fixture or application context, units, conditions, date, limitations, review owner and public disclosure approval. If any of these is missing, publish the gap as a limitation or do not publish the item.

## Evidence ladder

| Level | Evidence | Minimum publishable content | Best destination | Commercial use |
|---|---|---|---|---|
| 1 | TDS / parameters / standards | Source TDS revision, method, conditions, units and comparison caveat. | Product, selection and supplier-evaluation pages. | Screen a candidate; never declare equivalence. |
| 2 | Laboratory tests / benchmark | Sample IDs, method, fixture, pressure/BLT, environment, repeat count or stated limitation, result table and raw-image provenance. | `/benchmark-evidence/` plus linked money page. | Justify a controlled benchmark discussion. |
| 3 | Application evidence / sample validation | Anonymized geometry, interface map, assembly condition, acceptance logic, photo rights, scope and limitation. | Application cluster and case page. | Support a sample test plan. |
| 4 | Anonymous customer case study | Written permission, anonymization review, before/after metric with conditions, decision path and explicit non-transferability. | Case-study cluster. | Support qualification confidence; never identify a customer without authorization. |
| 5 | Production / second-source qualification | Approved scope, lot/site/revision controls, process window, pilot evidence, change notification and explicit publishing authorization. | Restricted summary only unless public permission exists. | Support RFQ readiness; avoid publishing confidential records. |

## Evidence backlog order

1. **P0 — Qualification evidence matrix template:** one reusable table for requirement → method → condition → evidence → decision owner. It strengthens the existing general second-source page without inventing a test.
2. **P0 — Case 001 evidence index:** a navigation block linking method, pressure, thickness, limitations and disclosure. Do not alter reported results.
3. **P1 — OBC gel process evidence package:** public-safe photos or diagrams plus documented dispense/void/cure measurement plan, only after provenance sign-off.
4. **P1 — Optical thin-interface requirements template:** gap, load, contact, contamination and reliability evidence checklist.
5. **P1 — AI power-interface requirements template:** interface-by-interface selection and validation checklist.
6. **P2 — Anonymous case-study pipeline:** publish only rights-cleared, attributable-to-method stories; do not turn application photos into customer cases.

## Publishing checklist

- Is the source original, rights-cleared and accurately labeled?
- Are method, sample, thickness/BLT, pressure, temperature and fixture visible where relevant?
- Does the page state what the evidence does **not** prove?
- Can an engineer reproduce or fairly interpret the comparison?
- Does the evidence point to one appropriate next step: benchmark, sample or technical discussion?
- Has a technical reviewer checked all numeric claims and units?

## Do not publish

- A generic photo as a customer case.
- A vendor TDS value as a guaranteed assembly outcome.
- A benchmark result without method, pressure/BLT and sample scope.
- A “replacement,” “equivalent,” “qualified,” “manufacturer” or “approved supplier” claim without the corresponding evidence and authorization.
- Production, customer, drawing, lot or pricing data without explicit public-release approval.
