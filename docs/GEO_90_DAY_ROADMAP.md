# GEO 90-Day Roadmap

## KPI order

1. Qualified inquiry
2. Benchmark request
3. Sample request
4. Second-source qualification
5. RFQ
6. AI citation
7. Google ranking
8. Organic traffic

Traffic is an observation metric, not the objective.

## Phase 1 — Discovery and measurement (Days 1–14)

**Outcome:** A stable, evidence-backed baseline rather than an assumed ranking story.

- Preserve sitemap, robots, canonical and Google verification implementation.
- Record live technical audit results monthly; fix only verified P0/P1 defects.
- When available, export GSC 28/90-day queries, pages, countries and devices; map each query to an existing URL.
- Capture only reproducible, dated public SERP snapshots. Otherwise mark ranking `NOT VERIFIED`.
- Define conversions: direct WhatsApp/email/call, benchmark request, sample request and private inquiry.

**Exit criterion:** One query-to-URL measurement table exists; no speculative index/ranking claims.

## Phase 2 — Money-page architecture (Days 15–35)

**Outcome:** Existing high-value URLs have an obvious decision path.

- Update, do not clone: `/china-thermal-interface-material-supplier/`, `/sp2000-alternative-evaluation/`, `/obc-thermal-material-supplier/`, `/optical-transceiver-tim-supplier/` and the AI server cluster.
- Make the primary conversion match intent: Benchmark for incumbent/alternative; sample discussion for controlled evaluation; direct technical discussion for uncertain application selection.
- Add reciprocal links between money pages, tools and evidence; avoid a new generic “TIM second source” page that would cannibalize the existing canonical hub.
- Standardize only the missing navigation/evidence labels; retain validated engineering text.

**Exit criterion:** Every money page answers one decision first, cites its evidence limits and leads to one primary CTA plus direct contact options.

## Phase 3 — Engineering evidence (Days 36–60)

**Outcome:** Reusable, condition-aware proof blocks instead of more generic articles.

- Publish a public-safe qualification-evidence matrix template.
- Index and cross-link Case 001 evidence by method, conditions, limitations and intended use.
- Prepare OBC, optical and AI evidence requirements; publish results only after source/provenance review.
- Use Level 1 and Level 2 evidence before proposing any customer or production story.

**Exit criterion:** At least three money pages contain condition-aware evidence tables or templates with clear limitations.

## Phase 4 — Case-study readiness (Days 61–70)

**Outcome:** A controlled pipeline, not fabricated social proof.

- Establish a rights, anonymization and technical-review checklist.
- Draft only anonymous, approval-pending cases with no customer identity or implied qualification.
- Prefer “engineering evidence case” over “customer success story” unless written authorization supports the latter.

**Exit criterion:** One case candidate has provenance and release approval; otherwise phase ends with no publication.

## Phase 5 — Authority and citation readiness (Days 71–80)

**Outcome:** Pages become easier to quote accurately without keyword stuffing.

- Add concise answer-first statements, tables, failure modes, FAQs and standards references where source-supported.
- Maintain author / updated date / scope / evidence-limit blocks.
- Review JSON-LD validity and use FAQPage only for maintained, visible FAQs.
- Track actual AI citations only when independently observable; do not use model-output anecdotes as rankings.

**Exit criterion:** Five priority pages meet the internal citation-readiness floor of 80 or have a documented evidence dependency.

## Phase 6 — Conversion learning (Days 81–90)

**Outcome:** Reduce friction between a useful page and a credible engineering conversation.

- Review which direct-contact path is used for money pages.
- Keep WhatsApp, email and call visible; do not force a long form.
- Give tools a short result-to-discussion bridge, not a lead gate.
- Simplify the TDS comparison first interaction only after observing tool use or interviewing users; retain the complete checklist function.

**Exit criterion:** Each money page has one primary next action, a private low-friction route and a reviewed follow-up owner.

## Operating rules throughout

- No daily-article quota.
- No unverified search-volume, ranking, supplier or performance claims.
- UPDATE existing intent-matched URL before CREATE.
- Publish only after source, cannibalization, technical review, build, canonical and link checks pass.
- Do not deploy or merge a change until explicitly authorized.
